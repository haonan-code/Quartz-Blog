
#### 工作成果和总结（结合2024年度个人规划）：
##### 个人工作成果汇报：
2024年物联网取证分析软件（后续简称物联网）的工作重点，主要聚焦在国产化移植、路由器、智能穿戴、无人机、智能家居等各个领域，进一步扩展了软件的适用场景，提升了软件竞争力；在新增功能的过程中，开发人员也修复了众多测试人员和技术人员反馈的众多软件bug，显著增强了软件的稳定性，旨在为用户提供更好的功能与服务；另外，开发人员积极响应上半年公司大力提倡的文档编写工作，补齐了往年并未记录文档的插件开发文档，规范了软件开发流程。
接下来我将详细介绍2024年主要的工作成果：
1. 物联网初步适配国产操作系统麒麟v10 x86和 arm 平台
	在国内大力推行信创的背景下，公司要求上半年所有产品均需要完成国产化操作系统的适配工作。所以2024年上半年物联网的主要工作就是完成麒麟v10 x86平台和arm平台的适配。适配国产操作系统的难点主要有以下几点：
	- 后端服务 master 中使用到了 Windows 平台下的库和函数
	- python 插件中有很多路径是直接是写死的，需要将路径修改为跨平台支持的方式
	- python 插件缺失库、库与库不兼容，通过源码安装的 python 环境缺少标准库中的某些库
	- electron 打包 Linux 端的软件包
	- 使用 dpkg 构建 deb 安装包
	- 软件图标异常、安装卸载失败、软件无法启动以及后台报错等一系列异常
	由于本人缺乏在 Linux 系统下进行开发的经验，实际开发中遇到的问题不计其数。好在有晖哥、陈汝峰和张雨等同事的帮助，我才得以在上半年完成物联网软件在国产操作系统的移植工作。虽然稍有延期1~2个工作日，但总体上还是完成。
2. 支持Linux x86 和 arm 双平台的 deb 包每日构建工作
	由于Windows平台和Linux平台的安装包不同，故新版本的每日构建工作需要针对Linux系统进行修改适配。完成x86和arm平台的物联网移植工作后，紧接着我又开始着手于两个平台的 deb 安装包的每日构建工作。在这期间，我参考了雷电app已经部署好的每日构建脚本，梳理其打包流程，学习了如何编写 bash 脚本，最终完成两个平台deb 安装包的每日构建脚本。
3. 新增路由器支持
	2024年依旧在扩大对路由器型号的支持工作，今年共计增加了对七个型号路由器的支持，并且支持对刷写了OpenWrt 系统的路由器进行固件的提取与分析。具体路由器新增型号如下：
	- 新华三ER2200G2企业型路由器
	- 中兴E1630（商企版）路由器
	- 华为WS832路由器
	- 中国电信WR330
	- GL-MT3000
	- 小米AX3000T
	- 腾达F3
	由于新支持的路由器就是原本插件不支持的，所以在开发中不仅需要适配新系统，而且要兼顾旧版本插件代码。在本年度对刷写了 OpenWrt 系统的路由器也进行了支持，直接通过OpenWrt 提供的 ssh 端口对OpenWrt系统根目录打tar包，然后传输至本地进行解压分析。
4. 新增智能穿戴数据解析
	本年度对智能穿戴方面的支持也逐渐增多，由原先仅支持小米运动健康数据的导出，增加至对小米健康、华为健康、苹果健康和华为儿童健康手表的数据提取与分析，填补了对智能穿戴设备取证这一领域的空白。
5. 无人机飞行记录增强解析
	无人机检材方面，除了优化大疆txt飞行记录的解析之外，还额外增加对刷写 APM 固件的 Pixhawk 飞控飞行日志的解析，同时对技术同事反馈的csv格式的飞行记录也进行了解析的支持。
	大疆无人机加密txt飞行记录原先仅有一种解密方法，今年增加了两种解密方法，大大丰富了软件对大疆加密txt飞行记录的解密范围。
	分析结果相较于之前添加了飞行数据中心节点，记录了每段飞行记录的汇总信息和概览，与大疆DJI Fly软件尽可能保持一致，这样可以更加直观地比较每段飞行记录，方便办案人员进行取证分析。
6. 新增智能家居、摄像头 app 云数据获取
	本年度对智能家居领域也有了大幅度的支持，主要得益于雷电云的同事对各品牌摄像头和智能家居app的逆向支持。物联网中移植了雷电云米家、小爱音箱、小米摄像头、小蚁摄像头、乔安智联摄像头、小度音箱和凯迪仕门锁的插件，加强了物联网软件在智能家居、摄像头场景下的取证能力，增加了使用场景。
7. 工具箱新增镜像制作功能
	工具箱中新增对jffs2、squashfs 两种文件系统镜像的制作，并支持通过 ssh 打出路由器系统的tar包，便于后续使用镜像分析插件进行分析。
8. 导出报告插件支持导出资源文件
	由于新增的摄像头插件支持固定拍摄的图片、视频文件，而原先的csv导出和导出报告插件均不支持导出下载的资源文件。本年度我对上述两个插件进行了修复升级，使其支持在导出csv和html报告的同时拷贝资源文件，并支持在csv文件和html网页上点击可预览图片和视频文件。
9. 修复若干bug
	2024年初项目人员分工发生变换，插件、后端均由我一个人进行开发，所以今年修复的bug不仅仅有各个插件的bug，还有后端服务的bug。插件bug主要有：镜像解析失败、txt快取的路径错误、打印机插件运行失败、水星交换机、中兴路由器运行失败等等，后端服务主要是插件更新、一些工具函数的bug。
10. 编写开发文档
	另外，上半年我还积极响应上半年公司大力提倡的文档编写工作，补齐了往年并未记录文档的插件开发文档，规范了软件开发流程。
11. 完善国产化操作系统上的物联网软件
	初步完成软件的国产化移植后，接下来的几个迭代主要在Windows 平台进行开发。期间又添加了诸多新功能和修复了许多bug，Linux 平台移植完成后就未进行维护。年底的一个迭代又安排了对国产操作系统 Linux 端的维护工作。主要进行了对2024年Windows平台新增插件、功能的适配工作，以及修复了之前测试人员测出的 Linux 系统下软件暴露出的一系列问题。
	
##### 总结：
2024一整年的开发让我收获颇丰，积累了大量的实际工作经验，提升了个人开发能力。首先是经过软件国产化移植工作后，我对Linux系统更加熟悉了，同时也具备了在Linux系统下进行开发的能力；其次是通过对新加密方式的路由器进行支持，接触到了更多js逆向的内容，虽然还对js逆向还算不上掌握的程度，但也在慢慢积累经验；通过对各个品牌健康软件导出的健康数据进行处理，我对数据分析也有了一定的了解；然后是在移植雷电云的插件过程中，从雷电云同事写的插件代码中也学习到了不少app逆向相关的知识；最后，通过这一年来后端master一个个bug 的修复工作，我对物联网后端的整体架构，目录结构，业务逻辑有了更加深刻的认识。
#### 本年度对自己不满意的地方：
1. 遇到比较难以理解的问题或者代码，在多次尝试未果后，容易萌生退意。这一点在后续的开发工程中要逐渐克服，尽量避免焦躁不安的情绪，遇到问题或不懂的地方冷静分析，求助他人。
2. 和领导沟通较少，没有什么反馈汇报。平时的开发周期中，遇到一些问题后总倾向于自己硬抗，未及时和领导沟通反馈。
3. 没有养成勤写文档的习惯。开发过程中，往往以影响思维流畅性和开发时间抗拒边开发边记录文档；开发完成后，又抗拒再回忆开发中遇到的细节问题从而遗漏文档的编写工作。
4. 时间利用率不高，空闲时间不会自主规划。碎片时间规划能力有待加强，空闲时间遇到感兴趣的内容被突如其来的事情打断后，就难以再继续学习，往往无法将整个内容学习完整，大多半途而废。
