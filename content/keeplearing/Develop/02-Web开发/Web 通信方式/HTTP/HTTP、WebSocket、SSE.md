## 介绍
### HTTP
HTTP 是典型的请求–响应协议，通信方向只能由客户端发起。服务端无法在无请求的情况下主动向客户端推送数据。  
HTTP/1.1 通过 Keep-Alive 复用 TCP 连接，HTTP/2 引入多路复用与头部压缩，HTTP/3 基于 QUIC 运行在 UDP 之上。

**优点**：生态成熟、无状态、可扩展性极好，几乎所有中间件与负载均衡都原生支持。
**缺点**：实时性差，无法满足高频推送场景。
**适用场景**：
适合 CRUD 接口、业务 API、页面请求等传统 Web 交互。

### WebSocket
WebSocket 先通过一次 HTTP Upgrade 握手，随后升级为基于 TCP 的全双工长连接。连接建立后，客户端和服务端都可以主动推送数据。

**核心特性**：长连接、低延迟、双向通信、支持文本与二进制帧。
**优点**：可以实现真正的实时双向通信，适合高频交互。
**缺点**：连接状态需要服务端维护，不利于无状态扩展，连接数管理和扩容复杂度较高。
**适用场景**：聊天系统、协同编辑、在线游戏、实时控制台。

### SSE(Server-Sent Events)
SSE 是基于 HTTP 的单向长连接机制。客户端发起请求后，服务端以 `text/event-stream` 形式持续向客户端推送数据。
通信方向只有：服务端 → 客户端。  
浏览器原生支持 `EventSource`，自带自动重连与断线恢复能力。

**优点**：实现简单、与现有 HTTP 基础设施完全兼容，适合推送类业务。
**缺点**：无法双向通信，不支持二进制数据，连接数受浏览器限制。
**适用场景**：系统通知、实时日志、监控告警、行情推送等场景。

## 对比
HTTP：请求驱动，客户端主动，非实时。  
WebSocket：全双工，任意一方可主动推送，实时性最强。  
SSE：单向长连接，仅服务端推送，实时性介于两者之间。
