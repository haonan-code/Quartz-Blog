#### 核心概念
IP+端口号通过 cloudflare 绑定到二级子域名，需要两个主要技术：
1. **域名解析（DNS）：** 将域名（或子域名）指向服务器的 IP 地址。
2. **反向代理：** 在服务器上部署一个代理服务器（如 Nginx，Caddy），它监听标准的 80 （HTTP）或 443 （HTTPS）端口，接收来自用户的请求，然后将这些请求转发给运行在特定端口（如 8282 或 8888）上的应用程序。

#### 步骤一：域名解析（DNS 配置）
登录域名注册商控制台（笔者域名托管于 Cloudflare ，故直接在 Cloudflare 上配置），添加或修改 DNS 记录：
1. **找到 DNS 管理/解析设置：** 在 Cloudflare 中找到 DNS 管理选项
2. **添加 A 记录（用于将一个域名映射到一个 IPv4 地址）：**
	- **主机记录**：
		- **如果你想使用主域名**（例如 example.com）指向你的服务，那么主机记录通常留空或填写 @。
		- **如果你想使用二级子域名**（例如 wallos.example.com 或 my-service.example.com）指向你的服务，那么主机记录就填写 wallos 或 my-service。
	- **记录类型**：选择 A 记录。
	- **记录值**：填写**服务器的公共 IP 地址**
	- **TTL**：DNS 记录生效时间
	- **举例**：
		- 如果你想用 wallos.yourdomain.com 指向你的服务器 IP 123.123.123.123：
			- 类型：A
			- 主机记录：wallos
			- 记录值：123.123.123.123
		- 如果你想用 yourdomain.com 指向你的服务器 IP 123.123.123.123：
			- 类型：A
			- 主机记录：@
			- 记录值：123.123.123.123
3. **等待 DNS 生效**：DNS 更改需要时间在全球范围内传播（这个时间称为 DNS 传播，TTL 越小传播越快）。你可以使用 ping wallos.yourdomain.com 或在线 DNS 查询工具来检查是否已经解析到你的服务器 IP
#### 步骤二：反向代理（Reverse Proxy）配置
这是最关键的一步，它将处理来自域名（默认 80/443 端口）的请求，并将其转发到你服务的实际端口（如 8282 或 8888）。、
**最流行的反向代理软件是 Nginx 和 Caddy。**
##### 使用 Nginx（功能强大，配置灵活）
1. **安装 Nginx**：
```bash
sudo apt update
sudo apt install nginx -y
```

2. **配置 Nginx**:
	创建一个新的 Nginx 站点配置文件。例如：对于 wallos.yourdomain.com:
	```bash
sudo vim /etc/nginx/sites-available/wallos.conf
```
	添加以下内容：
```nginx
server {  
    listen 80; # 监听 HTTP 80 端口  
    server_name wallos.yourdomain.com; # 你的域名或子域名  
  
    # 重定向 HTTP 到 HTTPS (强烈推荐)  
    # 如果你暂时不设置 HTTPS，可以先不加这几行  
    # return 301 https://$host$request_uri;  
  
    location / {  
        # 转发请求到 Wallos 服务运行的 IP 和端口  
        # 假设 Wallos 在服务器本地的 8282 端口  
        proxy_pass http://localhost:8282;  
  
        # 保持原始请求头，很重要！  
        proxy_set_header Host $host;  
        proxy_set_header X-Real-IP $remote_addr;  
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;  
        proxy_set_header X-Forwarded-Proto $scheme;  
  
        # 启用 WebSocket 代理 (如果你的应用需要，比如 Wallos 可能需要)  
        proxy_http_version 1.1;  
        proxy_set_header Upgrade $http_upgrade;  
        proxy_set_header Connection "upgrade";  
    }  
}  
```

3. **启用站点并测试配置**：
```bash
sudo ln -s /etc/nginx/sites-available/wallos.conf /etc/nginx/sites-enabled/
sudo nginx -t # 测试 Nginx 配置是否有语法错误
```

4. **加载 Nginx 配置**：
```bash
# Nginx 已在运行，重新读取配置文件，不中断当前连接
sudo systemctl reload nginx
或
sudo nginx -s reload

# Nginx 没有启动，更新 Nginx 本身或模块时，需要启动
sudo systemctl restart nginx
# 或 sudo systemctl start nginx
# 配置开机自启
sudo systemctl enable nginx
```
5. **配置服务器防火墙（UFW）**：
	如果开启了 UFW，需要放行 80 和 443 端口：
```bash
sudo ufw allow 'Nginx Full' # Nginx Full 规则包含了 80 和 443
# 或单独允许
# sudo ufw allow 80/tcp
# sudo ufw allow 443/tcp
sudo ufw reload # 重载防火墙
```
##### 使用 Caddy（更简单，自动 HTTPS）
Caddy 是一个现代 Web 服务器，最突出的特点是**自动 HTTPS**（通过 Let's Encrypt），配置起来非常简单。
1. **安装 Caddy**：
```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https  
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-archive-keyring.gpg  
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list  
sudo apt update  
sudo apt install caddy -y
```
2. **配置 Caddyfile**：
```bash
sudo vim /etc/caddy/Caddyfile
```
删除原有内容，添加以下内容：
```bash
wallos.yourdomain.com{ # 你的域名或子域名
	reverse_proxy localhost:8282 # 转发到 Wallos 服务运行的 IP 和端口
}
```
就这么简单！Caddy 会自动处理 HTTP 到 HTTPS 的重定向，并为你申请和续期 Let's Encrypt 证书。
3. **测试并启动 Caddy**：
```bash
sudo caddy validate -c /etc/caddy/Caddyfile # 验证配置文件
sudo systemctl enable caddy # 设置开机自启
sudo systemctl restart caddy # 重启 Caddy 服务
```

4. **配置服务器防火墙（UFW）**：
	如果开启了 UFW，需要放行 80 和 443 端口：
```bash
sudo ufw allow 'Caddy' # Caddy 规则包含了 80 和 443
sudo ufw reload
```
#### 步骤三：二级子域名
**强烈推荐建立二级子域名**，理由如下：
- **清晰性和组织性**：不同的服务使用不同的子域名，更易于管理和理解。例如：
	- wallos.yourdomain.com 用于 Wallos
	- blog.yourdomain.com 用于博客
	- admin.yourdomain.com 用于管理后台
	- api.yourdomain.com 用于 API 服务 这样比 yourdomain.com/wallos、yourdomain.com/blog 等方式要清晰得多，也避免了路径冲突。
- **SSL/TLS 证书管理**：
	- 为不同的子域名申请证书非常方便（特别是使用 Let's Encrypt），它们可以各自拥有独立的证书
	- 管理主域名下的不同路径会导致证书配置复杂，甚至可能出现混淆内容警告
- **服务独立性**：每个子域名可以独立指向不同的服务器或不同的应用程序，或者使用不同的配置。例如，你的 wallos 可以在一台服务器上，而你的博客在另一台服务器上
- **负载均衡和扩展**：在未来需要扩展服务时，基于子域名的分离更容易实现负载均衡和微服务架构
- **Cookie 隔离**：不同子域名下的 Cookie 是隔离的，提高了安全性

**什么情况下不适用二级子域名？**
- 如果你只有一个服务，并且这个服务就是你网站的全部内容，那么直接将主域名 (yourdomain.com) 指向它也可以。
- 如果你的服务本身就是一个大型的、包含多个内部路径的网站（例如一个 WordPress 博客），那么你可能就直接用主域名。

#### 总结
1. **DNS 解析**： 将你的域名（或子域名）的 A 记录指向你的服务器 IP。
2. **反向代理**： 在服务器上安装并配置 Nginx 或 Caddy，监听 80/443 端口，并将请求转发到你服务实际运行的端口（如 8282）。
3. **强烈建议使用二级子域名**来组织和管理你的不同服务，这在长期维护和扩展中具有巨大优势。
    
这样配置后，用户访问 `http(s)://wallos.yourdomain.com` 就会被反向代理接收，然后透明地转发到 http://localhost:8282 上的 Wallos 服务。用户甚至不会知道 Wallos 实际运行在哪个端口上，因为他们只与 80/443 端口打交道！
