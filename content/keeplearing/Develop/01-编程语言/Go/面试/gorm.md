#### 什么是 orm 框架？
**对象-关系映射（ORM）系统**，实现了 **程序对象** 到 **关系数据库数据** 的映射
#### gorm 框架的概念和作用
##### 什么是 gorm
GORM 是 Go 语言中最流行的 ORM（Object-Relational Mapping）框架之一，它的主要作用是：
**让开发者通过操作 Go 语言的结构体，就可以轻松完成对数据库的增删改查（CRUD），而不用写 SQL 语句。**
##### gorm 核心作用
- **ORM 映射**：将**结构体**映射为**数据库表结构**
- **CRUD 操作**：提供**链式 API** 快速执行增删改查
- **自动建表迁移**：**根据模型结构自动创建或更新表结构**
- **事务控制**：提供事务函数支持
- **多数据库支持**：支持 MySQL、PostgreSQL、SQLite、SQL Server 等
- **关联关系映射**：支持一对一、一对多、多对多等关系
- **钩子机制**：支持 `BeforeCreate`、`AfterUpdate` 等生命周期回调
- **插件机制**：支持软删除、数据权限、日志等插件扩展

#### gorm 模型中的字段标签的作用
在 GORM 中，模型（Model）里的字段标签（Tag）是一种**用于指定字段与数据库之间映射关系**的机制，它决定了**字段如何被 GORM 识别、处理、存储到数据库中**。

字段标签主要用于：
**控制字段的列名、主键、自增、默认值、忽略字段、时间戳、约束条件、索引**等。
示例：
```go
type User struct {
	ID   uint   `gorm:"primaryKey"`         // 主键
	Name string `gorm:"column:username"`    // 映射列名
	Age  int    `gorm:"default:18"`         // 默认值
	Note string `gorm:"-"`                  // 忽略该字段
}
```
字段标签写在结构体字段后，用 `gorm:"..."` 包裹

#### gorm 自动建表
gorm 支持 Migration 特性，支持根据 Go Struct 结构自动生成对应的表结构。如果表已经存在不会重复创建。
**注意：gorm 的 AutoMigrate 函数，仅支持建表，不支持修改字段和删除字段，避免意外导致丢失数据。**
#### gorm 和原生的相比有什么优势？
1. **支持多种数据库**：`Gorm`支持多种关系型数据库，包括`MySQL`、`PostgreSQL`、`SQLite`和`Microsoft SQL Server`等，这使得它成为一个非常灵活的`ORM`库。
2. **提供强大的查询功能**：`Gorm`提供了许多强大的查询功能，如**条件查询、排序、分组、连接查询和原始`SQL`查询**等。这些功能使得开发人员可以轻松地执行复杂的数据库查询操作。
3. **支持事务处理**：`Gorm`支持事务处理，这意味着开发人员可以将一系列数据库操作放在同一个事务中，并且在任何一个操作失败时，事务会自动回滚，保证数据的完整性。
4. **支持模型关系映射**：`Gorm`支持模型之间的关系映射，包括一对一、一对多和多对多关系。这使得开发人员可以轻松地在不同的数据表之间建立关联。
5. **可扩展性强**：`Gorm`的可扩展性非常强，可以通过插件机制来扩展其功能。例如，可以通过插件来添加缓存、日志记录和自定义数据类型等功能。
#### gorm 增删查改
##### 插入
```go
db.Create(&User{Name: "Tom", Age: 20})
```
##### 查询
```go
var user User
db.First(&user, 1) // 根据主键查询
```
##### 更新
```go
db.Model(&user).Update("Age", 30)
```
##### 删除
```go
db.Delete(&user)
```

#### gorm 如何防止 SQL 注入（依赖注入）
##### 什么是依赖注入？
**SQL 注入 (SQL Injection)** 是一种常见的网络安全漏洞，它允许攻击者通过在应用程序的**输入字段中插入（或“注入”）恶意的 SQL 代码**，从而操纵应用程序后台数据库的查询逻辑。
##### 如何防止 SQL 注入（依赖注入）
**1.始终使用 GORM 提供的参数化查询方式**
```go
db.Where("name = ?", userInput).Find(&users)
```
> `?`会自动做参数绑定，GORM 会处理转义，防止注入。

**2.结构体筛选（推荐）**
```go
type User struct {
	Name string
}
db.Where(&User{Name: userInput}).Find(&users)
```
> 结构体的字段值会被 gorm 安全转义处理。

**3.在业务逻辑层对用户输入进行严格的验证和清理**
- **数据类型检查**
- **长度限制**
- **格式验证**
- **特殊字符过滤或转义**
#### gorm 与 xorm 区别
**gorm**：
- 社区活跃，文档完善，插件多
- 支持链式操作、事务嵌套、钩子（Hooks）、预加载、迁移等
- 插件支持丰富（如缓存、分页、软删）
- 更现代，企业级使用更多
**xorm**：
- 简单易上手，API 直白（类似传统数据库操作）
- 性能优秀，学习成本低
- 对外键/关联关系支持弱
- 项目维护状态较弱（开发基本停止）

#### `gorm.io/gorm`和`github.com/jinzhu/gorm`区别
1. `gorm.io/gorm`：是 GORM v2 及更高版本，活跃开发中，由 go-gorm 团队维护；
2. `github.com/jinzhu/gorm` ：GORM v1，已停止开发和维护。仓库已归档，仅用于历史参考；
3. `gorm.io/gorm` 使用的数据库驱动被拆分为独立的项目，例如：`github.com/go-gorm/mysql`，且它的 import 路径也变更为`gorm.io/driver/mysql`
