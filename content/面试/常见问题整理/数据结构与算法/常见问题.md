```go
func main() {  
	list := new([]int)  
	list = append(list, 1)  // 编译错误！
	fmt.Println(list)  
	  
	s1 := []int{1, 2, 3}  
	s2 := []int{4, 5}  
	s1 = append(s1, s2)  // 编译错误！
	fmt.Println(s1)  
}  
```

第一个 `append` 调用是因为 `new([]int)` 返回的是指针，与 `append` 期望的切片类型不匹配。
- **`list := new([]int)`**: 这行代码创建了一个指向 `[]int` 类型零值的**指针**。`new([]int)` 返回的是 `*[]int`，而不是 `[]int`。此时 `list` 是一个指向 `nil` 切片的指针。
- **`list = append(list, 1)`**: `append` 函数的第一个参数期望接收一个切片（`[]Type`），但你传入的是一个切片指针（`*[]int`）。Go 语言的类型系统是严格的，不允许直接将指针类型传递给期望切片类型的地方。
    - **错误类型：** **编译错误**，类似 `cannot use list (type *[]int) as type []int in append`。
    - **如何修正：** 你应该直接声明一个切片，或者在使用 `new` 之后，通过解引用来操作切片。
```go
// 修正方式 1：直接声明切片（更推荐）
var list []int // list 初始化为 nil 切片
list = append(list, 1)
fmt.Println(list) // 输出：[1]

// 修正方式 2：使用 new 后解引用（不常用，但技术上可行）
// listPtr := new([]int)
// *listPtr = append(*listPtr, 1) // 先解引用，再append
// fmt.Println(*listPtr) // 输出：[1]
```

第二个 `append` 调用是因为 `append` 第二个参数应为单个元素或解包后的元素列表，而不是一个完整的切片。
- **`s1 := []int{1, 2, 3}`**: 这行代码声明并初始化了一个 `int` 类型的切片 `s1`。
- **`s2 := []int{4, 5}`**: 这行代码声明并初始化了一个 `int` 类型的切片 `s2`。
- **`s1 = append(s1, s2)`**: 这里的 `append` 函数用法不正确。`append` 函数的第二个参数（及后续参数）应该是要添加的**元素**，而不是另一个切片。如果你想将一个切片的所有元素追加到另一个切片中，你需要使用 `...` 操作符（解包操作）。
    - **错误类型：** **编译错误**，类似 `cannot use s2 (type []int) as type int in append`。`append` 期望添加 `int` 类型的值，但你传入了 `[]int` 类型。
    - **关于“定长数组”和“溢出panic”的误解：**
        - **Go 语言的切片（slice）** 并不是定长数组。切片是一个动态数组的视图，它可以根据需要自动扩容（当容量不足时，会创建一个更大的底层数组，并将旧数据复制过去）。因此，切片不会因为元素数量增加而“溢出panic”。
        - 你说的“定长数组”是指 Go 语言的**数组（array）**，例如 `[3]int{1, 2, 3}`。数组的长度在声明时就固定了，且数组不支持 `append` 操作。但你这里使用的是切片 `[]int`，所以这个担忧是不存在的。
    - **如何修正：** 使用 `...` 操作符来解包 `s2` 的元素。
```go
s1 := []int{1, 2, 3}
s2 := []int{4, 5}
s1 = append(s1, s2...) // 正确的用法，将s2的元素逐个添加到s1
fmt.Println(s1) // 输出：[1 2 3 4 5]
```


```go
a := [2]int{1, 2}  
b := [3]int{1, 2}  
if a == b {  
	fmt.Println("equal")  
} else {  
	fmt.Println("no")  
}  
// 无法通过编译
```
**`if a == b`**:
- 关键就在这里！在 Go 语言中，只有当两个数组的**类型完全相同**时，它们才能进行比较。
    - 数组的类型由**元素类型**和**数组长度**共同决定。
    - 在这个例子中，`a` 的类型是 `[2]int`，而 `b` 的类型是 `[3]int`。尽管它们的元素类型都是 `int`，但它们的**长度不同**，所以它们被认为是**不同的类型**。
    由于 `a` 和 `b` 的类型不匹配，Go 编译器会报错，指出无法比较不同类型的数组。



```go
    a := []int{1, 2, 3, 4, 5}
    b := a[:3]
    fmt.Println(cap(a))
    fmt.Println(len(a))

    fmt.Println(cap(b))
    fmt.Println(len(b))

```

**结论：刚开始切片b指向的是原来的数组a，所以cap是一致的，但是当给b后面添加元素后，直接重新分配新的地址了！**


```go
package main

import "fmt"

func main() {
    c := make(chan int) // 无缓 channel
    for i := 0; i <= 10; i++ {
        c <- i
    }
    go func() {
        for item := range c {
            fmt.Println(item)
        }
    }()
}

```

因此，死锁发生的原因是：
- `main` Goroutine 尝试向一个**无缓冲 channel** 发送数据。
- 在发送的瞬间，**没有其他 Goroutine 准备好接收数据**。
- 导致 `main` Goroutine 被永久阻塞，程序进入死锁状态。Go 运行时会检测到这种无法恢复的死锁情况，然后导致程序崩溃并报告 `all goroutines are asleep - deadlock!`。
解决方案：
1. 使用带缓冲的 Channel
给予 channel 一定的容量，这样在缓冲区满之前，发送操作不会阻塞。
```go
package main

import "fmt"

func main() {
    c := make(chan int, 11) // 缓冲区大小设置为11，足以容纳所有数据
    for i := 0; i <= 10; i++ {
        c <- i
    }
    go func() {
        for item := range c {
            fmt.Println(item)
        }
    }()
    // 等待Goroutine执行完毕，否则main函数可能提前结束
    // 实际项目中会用更严谨的方式如sync.WaitGroup
    // 为了演示，这里加一个短时间阻塞
    // 或者直接关闭channel并让main函数处理所有读取
    // time.Sleep(time.Millisecond * 100)
    close(c) // 关闭channel，让range循环退出
}
```
2. 先启动 Goroutine，再发送数据
确保接收方 Goroutine 在发送方尝试发送之前就已经在“监听”了。
```go
package main

import "fmt"
import "sync" // 引入sync包来同步Goroutine

func main() {
    c := make(chan int)
    var wg sync.WaitGroup // 使用WaitGroup等待Goroutine完成
    wg.Add(1) // 增加一个计数器，表示有一个Goroutine需要等待

    go func() {
        defer wg.Done() // Goroutine完成时调用Done()
        for item := range c {
            fmt.Println(item)
        }
    }()

    for i := 0; i <= 10; i++ {
        c <- i
    }
    close(c) // 发送完所有数据后，关闭channel，让接收端的range循环结束
    wg.Wait() // 等待接收Goroutine完成
}
```


```go
package main

import "fmt"

type P struct {
	name string
}

// 带有**值接收者** `p P` 的方法 `setname`
// 调用 `setname` 方法时，Go 会将 `p` 实例的一个**副本**传递给这个方法
// 因此，在 `setname` 方法内部对 `p.name = n` 的修改，**只会作用于这个副本**，而不会影响到原始的 `p` 实例。
func (p P) setname(n string) string {
	p.name = n
	return n
}

// 这也是一个带有**值接收者** `p P` 的方法 `getname`。
// 它返回接收者 `p` 的 `name` 字段的值。
func (p P) getname() string {
	return p.name
}

func main() {
	p := &P{name: "zhangsan"} // `p` 变量现在是一个指向这个 `P` 实例的**指针**（类型是 `*P`）
	// 尽管 `p` 是一个指针 (`*P`)，但由于 `setname` 方法的接收者是**值类型 `P`**，Go 编译器会自动对 `p` 进行**解引用**，然后将 `p` 所指向的 `P` 实例的**一个副本**传递给 `setname` 方法
	// 在 `setname` 内部，这个副本的 `name` 字段被改为了 `"lisi"`
	fmt.Println(p.setname("lisi"))
	// 同样地，由于 `getname` 的接收者也是**值类型 `P`**，Go 会将 `p` 所指向的 `P` 实例的**另一个副本**传递给 `getname` 方法
	fmt.Println(p.getname())
}
// lisi
// zhangsan
```
这个结果涉及到 Go 语言中**方法接收者（Method Receivers）** 的一个重要概念：**值接收者（Value Receiver）与指针接收者（Pointer Receiver）**。
如何实现预期的“修改”行为？
```go
package main

import "fmt"

type P struct {
	name string
}

// setname 方法使用指针接收者
func (p *P) setname(n string) string { // 注意这里是 *P
	p.name = n // 修改的是指针指向的原始实例
	return n
}

// getname 方法依然可以使用值接收者，因为它不修改数据
func (p P) getname() string {
	return p.name
}

func main() {
	p := &P{name: "zhangsan"}
	fmt.Println(p.setname("lisi")) // 调用 setname，修改原始实例
	fmt.Println(p.getname())      // 调用 getname，读取修改后的原始实例
}
```
