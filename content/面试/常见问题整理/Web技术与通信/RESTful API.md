#### 知道 restful 吗
**RESTful** 是一种基于 **REST（Representational State Transfer，表述性状态转移）** 架构风格的 **Web API 设计规范**，主要用于客户端和服务器之间通过 **HTTP 协议** 进行通信。

它强调**资源**的概念、**统一的接口设计**，以及通过**标准的 HTTP 方法**（GET、POST、PUT、DELETE 等）来操作资源。
##### 优点
- ✅ 简洁统一：接口清晰，便于理解和维护。
- ✅ 与 HTTP 协议高度契合。
- ✅ 更容易缓存、可扩展性好。
- ✅ 跨平台、跨语言支持强。

#### restful,GET POST 请求的区别
> **GET 是用来“拿”资源，POST 是用来“交”资源。**

| 特性            | `GET`                           | `POST`                 |
| ------------- | ------------------------------- | ---------------------- |
| 🔄 **用途**     | 获取资源                            | 创建资源（或提交数据）            |
| 📩 **参数位置**   | 参数放在 URL 中，如 `/users?id=123`    | 参数放在请求体中               |
| 🔐 **安全性**    | **不安全**，参数暴露在 URL 中             | 相对安全，参数在请求体中，不容易被日志记录  |
| 📦 **数据大小限制** | 有限制，受 URL 长度限制（一般浏览器限制在 2KB 左右） | 数据量大时首选，没有明确限制（受服务器限制） |
| 🔁 **幂等性**    | ✅ 是幂等的，多次请求返回结果一样，不会改变服务器状态     | ❌ 非幂等，多次请求会多次创建资源或重复提交 |
| 🔖 **缓存**     | 可被浏览器缓存，适合查询                    | 不可被缓存                  |
| 📚 **使用场景**   | 获取数据、查询列表、详情页等                  | 提交表单、用户注册、评论发布等        |
